04 — HASH CHAIN OF SIGNED RECEIPTS

Zeno

Reason before action.
ProblemAgents act on a prompt, not a boundary
Coding agents can edit your files, run your build, and push your commits — and each one asks you to trust a prompt. A prompt is a suggestion, not a boundary.
ContributionA local-first approval kernel
  • A local-first approval kernel sits between what an agent proposes and what actually runs. Every side-effecting action becomes a content-addressed "held proposal"; you approve the exact action, a compare-and-swap confirms the world hasn't moved, and exactly one execution is allowed.
  • A model can propose but never approve — structurally: the agent holds a proposer token the approval route rejects with 403, and Tier 4 payment/biometric effects are permanently unreachable.
  • Three products over one gate: Command (orchestrator), Forge (governed coding agent), and Counsel (consent-gated meeting notes).
Proof18 flows pass · signed receipt ledger
16 packages with zero runtime dependencies. Every result lands on an Ed25519-signed, hash-chained receipt ledger. The end-to-end suite passes 18 flows, 0 failed.

05 — A TREE OF CHARACTERS, NOT A STRING

Weft

Two people. One document. No lost edits.
ProblemEdit together, one goes offline
Two people edit the same paragraph and one drops offline for an hour. Naive systems overwrite work, force a conflict decision, or block editing.
ContributionA from-scratch Fugue CRDT
  • Weft stores the document as a tree of characters, not a string, using a from-scratch Fugue sequence CRDT (Weidner & Kleppmann, 2023) — every character carries a permanent (replica, counter) identity, so two peers converge with no "resolve conflict" dialog.
  • Honest sync states — in memory, "on this device" (IndexedDB), and "Saved" (append + fsync + server ack). The green Saved pill comes from the ack, never a timer.
  • The server is a pure relay and log writer that never imports CRDT semantics, so a server bug can't quietly change a merge.
Proof613 tests · 100k-op benchmark · live
613 Vitest cases, a 100,000-operation benchmark, and 33 real-browser Chromium cases including offline/reconnect and corrupt-storage recovery. Live at weft-abheet.fly.dev.

06 — TYPED FUNNEL

Vantage

Ask in English. See the SQL. Trust the number.
ProblemAn LLM writing SQL isn't checkable
Analytics tools answer with numbers you can't check. Let an LLM write the SQL and the number becomes both unverifiable and easy to talk into anything.
ContributionThe model fills a typed spec, not SQL
  • The model never writes SQL: it fills a typed QuerySpec (funnel, retention, trend, paths, count), and a pure compiler turns it into a parameterized SELECT, run as a read-only Postgres role, in a read-only transaction, with a 5-second timeout and row caps.
  • Exposed as an MCP server with 8 read-only tools — no run_sql, no ask — so Claude can query it with no key of its own, and every result carries the exact SQL it ran.

07 — CIPHERTEXT SCATTER

ShieldAI

The private key never leaves the browser.
ProblemScore sensitive numbers without sending them
You want a score computed on sensitive numbers without handing the raw numbers — or the private key — to the server.
ContributionCompute on ciphertext (Paillier)
  • An educational Paillier demo: the browser generates a 1024-bit keypair, encrypts four derived indicators, and sends only the public modulus and ciphertexts. The server adds the encrypted numbers and returns a total the browser decrypts locally to 37.5/100.
  • Partial (additive) homomorphic encryption is exactly what a weighted sum needs — the server computes on ciphertext and never sees a plaintext value.
  • Honest-but-curious threat model, stated plainly: no zero-knowledge range proof, so it doesn't defend against a client lying about its own inputs — and the demo says so.
ProofKey never leaves the browser · 8+19 gates
The raw fields and the private key never reach the server, and logging is payload-free. Verified by 8 backend tests and a 19-group browser gate. Live at shieldai-abheet19.fly.dev, with /version proving the exact commit.

10 — ONE LIGHTNESS LADDER

glass

A theme owns hue. The system owns everything else.
ProblemVisual drift across products is easy to miss
Eight of my projects landed on the same glass surface without ever sharing a stylesheet — and visual drift across products is easy to introduce and hard to catch.
ContributionOne design grammar, eight numbers per theme
  • The extraction: one importable, framework-neutral design grammar — semantic OKLCH tokens, eight themes, six component sheets, and a Tailwind v3 adapter, with no React and no runtime.

Proof814 assertions · 16 palettes · used in prod
